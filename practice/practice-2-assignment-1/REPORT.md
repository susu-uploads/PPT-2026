# Практическая работа №1

Бабушкин Михаил Вадимович. Технологии параллельного программирования.

## Реализация

Задание 1 выполнено настройкой проекта CMake с OpenMP вместо интерфейса Visual Studio. task-2 создаёт четыре потока, несмотря на предварительную настройку восьми. task-3 читает k и выводит все номера; флаг --even включает зависимую модификацию с чётными номерами.

Исходники находятся непосредственно в каталоге практики. Каждый независимый `.cpp` имеет собственную точку входа; вся практика собирается одной командой CMake. Зависимые варианты выбираются флагами. Формулировки заданий и оригинальные вложения сохранены.

## Среда и сборка

Apple M4 Max; 14 физических и логических CPU-ядер, 36 GiB RAM; macOS 15.8, ARM64.

```text
cmake 4.4.4
libomp 23.1.3
llvm 23.1.3_1
open-mpi 5.0.11
```

Команды выполняются из каталога этой практики. Первоначальная установка зависимостей:

```bash
brew install llvm libomp open-mpi cmake
```

```bash
cmake -S . -B .cache/build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER="$(brew --prefix llvm)/bin/clang++" \
  -DOpenMP_CXX_INCLUDE_DIR="$(brew --prefix libomp)/include" \
  -DOpenMP_omp_LIBRARY="$(brew --prefix libomp)/lib/libomp.dylib"
cmake --build .cache/build -j 4
python3 verify.py
```

Число потоков для программ без собственного параметра задаёт `OMP_NUM_THREADS`; динамическое изменение размера команды отключено. MPI-программы запускаются через `mpirun --bind-to none -np P`. Порядок строк от разных исполнителей не фиксируется.

## Контрольные вопросы

### 1. Что такое OpenMP? Какие модели он реализует? Опишите модели и их связь.

OpenMP — стандарт директив, библиотечных функций и переменных окружения для общей памяти. В модели fork–join главный поток создаёт команду для параллельной области; по завершении области команда синхронизируется. Общие данные доступны команде, частные копии принадлежат отдельным потокам.

### 2. В каких языках реализован этот стандарт? Из каких частей состоит реализация в Visual Studio?

Стандарт определён для C, C++ и Fortran. В Visual Studio реализация включает обработку директив компилятором, заголовок omp.h и библиотеку выполнения; поддержка включается /openmp. Здесь используются Clang и libomp, подключаемые CMake через OpenMP::OpenMP_CXX.

### 3. Какие существуют варианты задания количества нитей в параллельном регионе? Сколько нитей будет создано, если указаны оба варианта с разными значениями? Что конкретно делает функция omp_set_num_threads()?

Число потоков задают OMP_NUM_THREADS, omp_set_num_threads() и num_threads(). Явный num_threads для конкретной области имеет приоритет над настройкой omp_set_num_threads. Последняя меняет настройку для последующих параллельных областей текущей задачи. В task-2 при настройках 8 и 4 фактически получены четыре строки. Динамическое изменение размера команды отключено.

### 4. Как идентифицируются нити в OpenMP? Для чего это нужно? Приведите содержательный пример. Совпадают ли эти идентификаторы с идентификаторами потоков в ОС?

omp_get_thread_num() возвращает номер 0..k−1 внутри текущей команды, omp_get_num_threads() — размер команды. Номер удобен для распределения строк матрицы или диапазонов суммирования. Это не идентификатор потока ОС; в разных командах номера могут повторяться.

### 5. Каков порядок вывода сообщений нитями? Всегда ли он одинаков? Чем определяется этот порядок?

Порядок сообщений не задан: его определяют планировщик и ход выполнения потоков. Один вызов printf формирует целую строку, но не задаёт порядок строк. Для проверки сравнивается состав сообщений, а не порядок. Для гарантированного порядка потребовалась бы отдельная синхронизация.

## Вывод

Получены четыре Hello World и полный набор идентификаторов для k=1,2,4. Вариант --even сохраняет только чётные номера. Подтверждён приоритет num_threads; изменение порядка строк не меняет правильность результата.
