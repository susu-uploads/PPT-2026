# Практическая работа №1

## Что надо сделать

### Задание 1. Создание проекта с поддержкой OpenMP

По условию методических указаний необходимо создать проект в MS Visual Studio 2010 с поддержкой OpenMP.

### Задание 2. Многопоточная программа «Hello World!»

Написать OpenMP-программу, которая создаёт четыре потока. Каждый поток должен вывести строку `Hello World!`.

Входных данных нет. Результат — четыре строки `Hello World!`.

### Задание 3. Программа «I am!»

Написать программу, которая читает количество потоков `k`, создаёт команду из `k` потоков и выводит для каждого потока его номер и размер команды в формате:

```text
I am <Номер нити> thread from <Количество нитей> threads!
```

Затем изменить программу так, чтобы сообщения выводили только потоки с чётными номерами. Количество созданных потоков при этом должно остаться равным `k`.

## Что сделано

Бабушкин Михаил Вадимович. Технологии параллельного программирования.

Проект настроен для сборки на macOS через CMake, Clang и библиотеку OpenMP `libomp`. Для заданий 2 и 3 созданы отдельные программы `task-2` и `task-3`. Первая создаёт четыре потока: параметр `num_threads(4)` имеет приоритет над предварительной настройкой `omp_set_num_threads(8)`. Вторая получает `k` и режим `even`: `0` — вывод всех потоков, `1` — только чётных. Функция `main` читает параметры из аргументов запуска через `std::stoi` либо из `std::cin`, затем вызывает `run(int k, bool even)` с OpenMP-логикой. При полном наборе аргументов программа не обращается к stdin. Предполагается корректный ввод: положительное `k` и режим `0/1`.

Исходники находятся непосредственно в каталоге практики. Каждый независимый `.cpp` имеет собственную точку входа; вся практика собирается одной командой CMake. Вариант задания 3 выбирается параметром `even`.

### task-2.cpp

```cpp
// Подключает объявление std::printf для вывода текста.
#include <cstdio>
// Подключает объявления функций настройки и управления потоками OpenMP.
#include <omp.h>

// Объявляет точку входа программы и открывает тело функции main.
int main() {
    // Отключает динамическую корректировку количества потоков библиотекой OpenMP.
    omp_set_dynamic(0);
    // Задаёт восемь потоков для последующих областей без собственного параметра num_threads.
    omp_set_num_threads(8);
    // Создаёт параллельную область из четырёх потоков; num_threads(4) переопределяет настройку 8.
    #pragma omp parallel num_threads(4)
    // Открывает блок, который каждый поток команды выполнит один раз.
    {
        // Выводит строку Hello World! и перевод строки от имени текущего потока.
        std::printf("Hello World!\n");
        // Закрывает параллельный блок; неявный барьер ожидает завершения всех потоков команды.
    }
    // Закрывает main; достижение конца этой функции означает успешное завершение с кодом 0.
}
```

### task-3.cpp

```cpp
// Подключает объявление std::printf для форматированного вывода сообщений потоков.
#include <cstdio>
// Подключает std::cin для чтения параметров, std::cout для приглашения и std::cerr для сообщения о числе аргументов.
#include <iostream>
// Подключает функции OpenMP для настройки команды и получения номеров потоков.
#include <omp.h>
// Подключает std::stoi для преобразования аргументов запуска в числа.
#include <string>

// Открывает run, которая выполняет задание с уже полученными параметрами.
int run(int k, bool even) {
    // Отключает динамическую корректировку запрошенного количества потоков OpenMP.
    omp_set_dynamic(0);
    // Создаёт параллельную область, явно задавая размер команды равным прочитанному k.
    #pragma omp parallel num_threads(k)
    // Открывает блок, выполняемый каждым потоком созданной команды.
    {
        // Сохраняет в локальной переменной rank номер текущего потока внутри команды, начиная с 0.
        const int rank = omp_get_thread_num();
        // Разрешает вывод всем потокам при even=false, а при even=true — только потокам с чётным rank.
        if (!even || rank % 2 == 0) {
            // Начинает вызов printf с двумя числовыми подстановками и передаёт rank для первой из них.
            // Передаёт фактический размер команды для второй подстановки и завершает вызов printf.
            std::printf("I am %d thread from %d threads!\n", rank, omp_get_num_threads());
        }
        // Закрывает параллельный блок; перед выходом все потоки команды проходят неявный барьер.
    }
    // Возвращает код успешного завершения после выполнения команды потоков.
    return 0;
    // Закрывает run.
}

// Открывает main; argc содержит число аргументов вместе с именем программы, argv — их строки.
int main(int argc, char **argv) {
    // Объявляет количество потоков и режим вывода.
    int k;
    bool even;

    // Получает оба параметра из полного набора аргументов запуска.
    if (argc == 3) {
        k = std::stoi(argv[1]);
        even = std::stoi(argv[2]);
        // При отсутствии аргументов запрашивает оба параметра через стандартный ввод.
    } else if (argc == 1) {
        std::cout << "Введите количество потоков и режим (0 — все, 1 — только чётные): ";
        std::cin >> k >> even;
        // Сообщает об ошибочном количестве аргументов без перехода к stdin.
    } else {
        std::cerr << "Использование: task-3 [k even]\n";
        return 2;
    }

    // Передаёт полученные значения функции выполнения задания.
    return run(k, even);
    // Закрывает main.
}
```

### Среда и сборка

Apple M4 Max; 14 физических и логических CPU-ядер, 36 GiB RAM; macOS 15.8, ARM64.

```text
cmake 4.4.4
libomp 23.1.3
llvm 23.1.3_1
```

Команды выполняются из каталога этой практики. Первоначальная установка зависимостей:

```bash
brew install llvm libomp cmake
```

```bash
cmake -S . -B .cache/build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER="$(brew --prefix llvm)/bin/clang++" \
  -DOpenMP_CXX_INCLUDE_DIR="$(brew --prefix libomp)/include" \
  -DOpenMP_omp_LIBRARY="$(brew --prefix libomp)/lib/libomp.dylib"
cmake --build .cache/build -j 4
```

В обеих программах размер команды явно задаёт параметр `num_threads`: четыре потока для `task-2` и введённое значение `k` для `task-3`. Переменная окружения `OMP_NUM_THREADS` не переопределяет этот параметр. Динамическое изменение размера команды отключено. Порядок строк от разных потоков не фиксируется.

### Проверка

Практика проверяется сборкой и прямым запуском программ без тестовой обвязки. `task-2` должна вывести четыре строки `Hello World!`. Для `task-3` проверяются полный набор и только чётные номера потоков при `k = 1, 2, 4`, как через аргументы запуска, так и через stdin. Сравниваются количество и состав сообщений; случайный порядок строк не влияет на правильность результата.

При запуске с аргументами stdin не используется и приглашение не выводится. Без аргументов программа выводит одно приглашение и читает оба значения. Частичный или избыточный набор аргументов завершает программу с кодом 2 без чтения stdin.

## Контрольные вопросы

### 1. Что такое OpenMP? Какие модели он реализует? Опишите модели и их связь.

OpenMP — стандарт директив, библиотечных функций и переменных окружения для общей памяти. В модели fork–join главный поток создаёт команду для параллельной области; по завершении области команда синхронизируется. Общие данные доступны команде, частные копии принадлежат отдельным потокам.

### 2. В каких языках реализован этот стандарт? Из каких частей состоит реализация в Visual Studio?

Стандарт определён для C, C++ и Fortran. В Visual Studio реализация включает обработку директив компилятором, заголовок omp.h и библиотеку выполнения; поддержка включается /openmp. Здесь используются Clang и libomp, подключаемые CMake через OpenMP::OpenMP_CXX.

### 3. Какие существуют варианты задания количества нитей в параллельном регионе? Сколько нитей будет создано, если указаны оба варианта с разными значениями? Что конкретно делает функция omp_set_num_threads()?

Число потоков задают OMP_NUM_THREADS, omp_set_num_threads() и num_threads(). Явный num_threads для конкретной области имеет приоритет над настройкой omp_set_num_threads. Последняя меняет настройку для последующих параллельных областей текущей задачи. В task-2 при настройках 8 и 4 фактически получены четыре строки. Динамическое изменение размера команды отключено.

### 4. Как идентифицируются нити в OpenMP? Для чего это нужно? Приведите содержательный пример. Совпадают ли эти идентификаторы с идентификаторами потоков в ОС?

omp_get_thread_num() возвращает номер 0..k−1 внутри текущей команды, omp_get_num_threads() — размер команды. Номер удобен для распределения строк матрицы или диапазонов суммирования. Это не идентификатор потока ОС; в разных командах номера могут повторяться.

### 5. Каков порядок вывода сообщений нитями? Всегда ли он одинаков? Чем определяется этот порядок?

Порядок сообщений не задан: его определяют планировщик и ход выполнения потоков. Один вызов printf формирует целую строку, но не задаёт порядок строк. Для проверки сравнивается состав сообщений, а не порядок. Для гарантированного порядка потребовалась бы отдельная синхронизация.
