# Практическая работа №4

Бабушкин Михаил Вадимович. Технологии параллельного программирования.

## Реализация

Задание 10 выполнено конфигурацией CMake с Open MPI. task-11 выводит ранг и размер коммуникатора. task-12 соответствует тексту условия: чётный ранг — FIRST, нечётный — SECOND, ранг 0 выводит общее число процессов. В примере PDF соответствие обратное; реализация следует тексту условия.

Исходники находятся непосредственно в каталоге практики. Каждый независимый `.cpp` имеет собственную точку входа; вся практика собирается одной командой CMake. Зависимые варианты выбираются флагами.

## ИСХОДНЫЙ КОД

### mpi-hello-world.cpp

```cpp
#include <cstdio>
#include <mpi.h>

int main(int argc, char **argv) {
  // Инициализация выполняется один раз в каждом уже запущенном MPI-процессе.
  MPI_Init(&argc, &argv);
  int rank, size;
  // Ранг и размер определяются относительно MPI_COMM_WORLD.
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &size);

  // Каждый процесс печатает одну строку; порядок строк между процессами не задан.
  std::printf("I am %d process from %d processes!\n", rank, size);

  // Все обмены завершены; процесс освобождает ресурсы MPI перед выходом.
  MPI_Finalize();
}
```

### mpi-even-odd.cpp

```cpp
#include <cstdio>
#include <mpi.h>

int main(int argc, char **argv) {
  // Инициализация выполняется один раз в каждом уже запущенном MPI-процессе.
  MPI_Init(&argc, &argv);
  int rank, size;
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &size);

  // Нулевой процесс сообщает размер группы, остальные выбирают метку по тексту условия.
  if (rank == 0)
    std::printf("%d processes.\n", size);
  else
    std::printf("I am %d: %s!\n", rank, rank % 2 == 0 ? "FIRST" : "SECOND");

  // Все обмены завершены; процесс освобождает ресурсы MPI перед выходом.
  MPI_Finalize();
}
```

Команды выполняются из каталога этой практики. Первоначальная установка зависимостей:

```bash
brew install llvm libomp open-mpi cmake
```

```bash
cmake -S . -B .cache/build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER="$(brew --prefix llvm)/bin/clang++"
cmake --build .cache/build -j 4
python3 verify.py
```

Число потоков для программ без собственного параметра задаёт `OMP_NUM_THREADS`; динамическое изменение размера команды отключено. MPI-программы запускаются через `mpirun --bind-to none -np P`. Порядок строк от разных исполнителей не фиксируется.

## Контрольные вопросы

### 1. Что такое MPI? Какую модель параллельного программирования он реализует, на какую архитектуру ориентирован? Как Вы подключили его в используемой системе программирования?

MPI — стандарт обмена сообщениями между процессами с отдельными адресными пространствами; типичная модель — SPMD. Он применим как к распределённым узлам, так и к процессам одного компьютера. Здесь установлен Open MPI, а CMake подключает MPI::MPI_CXX; запуск выполняется mpirun. В Visual Studio аналогичное подключение требует заголовков, библиотек и среды выполнения реализации MPI.

### 2. Чем в MPI реализованы параллельно выполняемые подзадачи? Как и в какой момент они запускаются? До каких пор существуют? Чем идентифицируются?

Подзадачи выполняют процессы ОС. mpirun запускает указанное число экземпляров исполняемого файла; MPI_Init подключает уже запущенный процесс к MPI, а не создаёт остальные процессы. Процесс работает до завершения программы; MPI_Finalize завершает работу с MPI. Внутри коммуникатора процесс определяется рангом.

### 3. Что такое коммуникатор? Как учитываются входящие в него процессы?

Коммуникатор задаёт группу процессов и отдельный контекст обмена сообщениями. MPI_COMM_WORLD содержит процессы исходного запуска. Ранги нумеруются от 0 до size−1 и имеют смысл относительно конкретного коммуникатора.

### 4. Что делают функции MPI_Init() и MPI_Finalize()? Какую роль играют? Сколько раз могут быть вызваны?

MPI_Init инициализирует MPI, MPI_Finalize освобождает его ресурсы после завершения обменов. Каждый процесс вызывает инициализацию и завершение ровно по одному разу. MPI_Init_thread является альтернативой MPI_Init для указания требований к потокам. Повторная инициализация после Finalize не допускается.

### 5. Для чего любой параллельной программе нужна информация о количестве запущенных процессов(потоков) и идентификатор текущего объекта?

Ранг позволяет выбрать роль процесса и свою часть работы, size задаёт число участников и границы распределения. В task-12 ранг 0 печатает число процессов, остальные выбирают FIRST/SECOND по чётности. Без этих значений все экземпляры выполняли бы одинаковую роль без координации.

## Вывод

Каждый процесс вывел правильный ранг и размер группы. FIRST/SECOND проверены по текстовому условию, включая отдельную роль ранга 0. Работа запускается через Open MPI на macOS без Microsoft MPI.
