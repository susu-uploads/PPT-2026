# Практическая работа №7

Бабушкин Михаил Вадимович. Технологии параллельного программирования.

## Реализация

Задание 30 выполнено настройкой CMake с MPI и OpenMP. task-31 читает число потоков k и печатает все пары идентификаторов. task-32 читает N; число потоков задаёт OMP_NUM_THREADS. Режим по умолчанию hybrid; --mode serial и --mode openmp дают сопоставимые базовые расчёты в том же исходнике. Для чистого MPI используется task-18 практики 6 с той же формулой и компилятором.

Исходники находятся непосредственно в каталоге практики. Каждый независимый `.cpp` имеет собственную точку входа; вся практика собирается одной командой CMake. Зависимые варианты выбираются флагами. Формулировки заданий и оригинальные вложения сохранены.

## Среда и сборка

Apple M4 Max; 14 физических и логических CPU-ядер, 36 GiB RAM; macOS 15.8, ARM64.

```text
cmake 4.4.4
libomp 23.1.3
llvm 23.1.3_1
open-mpi 5.0.11
```

Команды выполняются из каталога этой практики. Первоначальная установка зависимостей:

```bash
brew install llvm libomp open-mpi cmake
```

```bash
cmake -S . -B .cache/build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER="$(brew --prefix llvm)/bin/clang++" \
  -DOpenMP_CXX_INCLUDE_DIR="$(brew --prefix libomp)/include" \
  -DOpenMP_omp_LIBRARY="$(brew --prefix libomp)/lib/libomp.dylib"
cmake --build .cache/build -j 4
python3 verify.py
```

Число потоков для программ без собственного параметра задаёт `OMP_NUM_THREADS`; динамическое изменение размера команды отключено. MPI-программы запускаются через `mpirun --bind-to none -np P`. Порядок строк от разных исполнителей не фиксируется.

Берётся максимум времени процессов. MPI_Init_thread, создание процессов, ввод, вывод и служебная редукция времени исключены. ## Контрольные вопросы

### 1. Для какого класса архитектур параллельных вычислительных систем предназначена гибридная (MPI + OpenMP) технология программирования?

Гибридная модель предназначена прежде всего для кластеров многопроцессорных узлов: MPI связывает процессы и узлы, OpenMP использует общую память внутри процесса. Она также применима к одному узлу, но не гарантирует выигрыша над чистым OpenMP.

### 2. Какими объектами ОС она оперирует?

MPI оперирует процессами ОС с отдельными адресными пространствами, OpenMP — потоками внутри процесса. Потоки процесса разделяют его память; между процессами данные передаются сообщениями.

### 3. Не противоречит ли ответу на предыдущий вопрос запуск данной программы на Вашем ноутбуке? Какую архитектуру он имеет?

Противоречия нет: ноутбук является одним узлом с общей памятью. На использованном Apple M4 Max доступно 14 CPU-ядер. Несколько MPI-процессов на нём имитируют распределение работы между процессами, а OpenMP создаёт команды потоков внутри них. Это не эксперимент на многоузловом кластере.

### 4. Можно ли в коде программы поменять порядок вложения блоков MPI и OpenMP (MPI_Init-MPI_Finalize внутри параллельного региона OpenMP)? Почему?

Нельзя переносить MPI_Init/MPI_Finalize внутрь области так, чтобы каждый OpenMP-поток вызывал их: инициализация и завершение допускаются один раз на процесс. В реализации MPI_Init_thread запрашивает MPI_THREAD_FUNNELED, проверяется предоставленный уровень, все MPI-вызовы делает главный поток вне параллельных областей. Для MPI-вызовов из других потоков нужен соответствующий уровень поддержки и иной порядок синхронизации.

### 5. Прокомментируйте порядок вывода номеров процессов и нитей.

Порядок строк между потоками и процессами не определён. Проверка task-31 требует все пары (ранг процесса, номер потока) и правильное P*K, независимо от порядка. Один printf используется для целой строки, но глобальную очередность это не задаёт.

### 6. Исходя из каких соображений в Задании № 32 выбран способ распределения итераций по процессам (количество, порядок выбора итераций)?

Каждая итерация интегрирования имеет одинаковую вычислительную стоимость. Диапазон разбивается на смежные блоки длины N/P; первые N mod P процессов получают ещё одну итерацию. Так сохраняются все итерации без дублирования, разница размеров не превышает единицы, поддерживается N<P.

### 7. Исходя из каких соображений в Задании № 32 выбран способ распределения итераций по нитям (статический/динамический, размер чанка)?

Внутри процесса используется static: одинаковая стоимость итераций не требует динамической балансировки. Размер блока оставлен реализации; крупные близкие по размеру диапазоны сокращают служебные расходы по сравнению с выдачей мелких блоков.

### 8. Замерьте время выполнения расчетов при различном количестве нитей и процессов, приведите результаты в таблице. Сравните со временем выполнения аналогичных заданий из предыдущих разделов. Прокомментируйте результат.

Результаты собственных измерений, параметры и сравнение с последовательным, чистым MPI и OpenMP расчётами приведены ниже в разделе экспериментов. Ускорение вычисляется относительно последовательной медианы при том же N; преимущества отдельных близких результатов нельзя считать статистически доказанными.

## Вывод

Гибридный расчёт сохраняет правильный результат при изменении числа процессов и потоков. На одном узле MPI, OpenMP и гибридная модель используют одни CPU-ядра; выбор сочетания зависит от размера задачи и накладных расходов. Таблица подтверждает ускорение большого расчёта, но не доказывает преимущество гибридной модели на кластере.
